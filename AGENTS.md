# AGENTS.md

Guidance for AI coding agents working in this repository. Human
contributors may find it useful too, but it is written for agents:
specific commands, specific file locations, no assumed prior context.

## Project overview

PERSUADE (**Param**e**tR**ic **SU**rviv**A**l mo**D**el s**E**lection) is
an R package that provides a standardized framework for selecting and
evaluating parametric survival models for time-to-event data, intended for
use in health-economic decision-analytic models. It builds on `flexsurv`,
`flexsurvcure`, `survival`, `muhaz`, `sft`, and `rms`.

Core entry points:

- `f_PERSUADE()` — fits Kaplan-Meier, Cox PH, standard parametric, spline,
  and cure survival models and returns an S3 object of class `"PERSUADE"`.
- `print.PERSUADE()` / `summary.PERSUADE()` / `plot.PERSUADE()` — S3
  methods for inspecting results.
- `f_generate_report()` — renders a PDF report via `rmarkdown`.
- `f_get_excel_template()` — copies a bundled Excel template for
  transferring fitted parameters into decision-analytic models.
- `f_run_dashboard()` — launches an interactive Shiny dashboard
  (`inst/shiny-dashboard/app.R`) wrapping the above; requires the
  Suggested packages `shiny`, `shinydashboard`, `DT`, `bslib`,
  `shinycssloaders`.

## Build, test, and check commands

This is a standard R package. From the repository root, in R:

```r
# Regenerate NAMESPACE/man/*.Rd from roxygen comments after editing R/ files
roxygen2::roxygenise()

# Run the test suite
devtools::test()               # or: testthat::test_check("PERSUADE")

# Full CRAN-style check
devtools::check()              # or: R CMD build . && R CMD check *.tar.gz

# Regenerate the bundled example dataset after editing its generator
source("data-raw/create_persuade_trial_data.R")

# Launch the dashboard locally
PERSUADE::f_run_dashboard()    # after devtools::load_all() or install
```

`DESCRIPTION` lists `flexsurv`, `flexsurvcure`, `muhaz`, and `sft` under
`Imports:` — all four must be installed for the package to load at all
(`R CMD INSTALL`, `pkgload::load_all()`, and `roxygen2::roxygenise()` all
enforce this). If you're working in an environment without CRAN access,
these may not be installable; see `MAP.md` for how a prior session handled
that constraint (short version: helper/logic code that doesn't need them
was tested directly; anything calling `f_PERSUADE()` was left for CI).

## Code style

- Base R throughout (no tidyverse dependency in package code); `data.table`
  is used in a few spots for performance.
- Functions are prefixed `f_` and documented with roxygen2 comments
  directly above the definition (`#'` blocks) — edit those, not the
  generated `man/*.Rd` files (they carry a "do not edit by hand" header).
- Exported functions go in `NAMESPACE` (`export(...)`) — normally
  regenerated by `roxygen2::roxygenise()`, not edited by hand.
- No formal linter is configured; match the existing style in the file
  you're editing (spacing, `<-` for assignment, roxygen doc style).

## Testing conventions

- Tests live in `tests/testthat/`, one `test_that()` per behavior, with a
  short comment block at the top of each file summarizing what it covers
  (follow the existing files' style).
- Tests that fit real survival models (via `flexsurv`/`flexsurvcure`) use
  `skip_on_cran()` and, where appropriate, `skip_if_not_installed()` for
  optional pieces (spline/cure models). Follow this pattern for new tests
  that exercise the model-fitting pipeline.
- Prefer TDD where practical: write the failing test first, then the
  minimal implementation to pass it. For pure-logic helpers (e.g. the
  dashboard's `f_dashboard_*()` functions), this is straightforward. For
  code that depends on `flexsurv`/`muhaz`/`sft`, still write the test
  first, but expect to verify it in an environment where those packages
  are installed.

## PR / commit conventions

- No enforced commit message format observed in history; write clear,
  imperative-mood messages describing the change and why.
- Keep `NEWS.md` updated for user-facing changes (new/changed exported
  functions, bundled data, behavior changes).
- If you regenerate `NAMESPACE`/`man/*.Rd` by hand (because `roxygen2`
  isn't runnable in your environment), keep the exact format of the
  existing generated files, including the `% Generated by roxygen2: do not
  edit by hand` header, and validate with `tools::parse_Rd()` — then flag
  in your PR description that this should be re-verified with a real
  `roxygen2::roxygenise()` run once possible.
